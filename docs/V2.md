# KAPTURE v2 — Overlay en jeu, variantes du bouton, échanges avec le jeu, suivi

Ce document fait foi pour la v2. Il **complète** [`API.md`](../API.md) (contrat v1, inchangé sauf les ajouts signalés ici).
Mêmes standards que la v1 : JSON en **français snake_case**, erreurs `{"message": "…"}` en français,
dates ISO 8601 UTC avec millisecondes (`2026-11-17T14:32:05.120Z`), validation Jakarta.

## 1. Fonctionnalités

| Fonctionnalité | Ce que ça veut dire concrètement |
| --- | --- |
| **Affichage permanent** | Le jeu charge l'overlay (`/overlay/?session=42&user=Storm_X9`) dans une iframe plein écran, fond transparent, par-dessus le jeu, pendant toute la session. Les clics traversent l'overlay sauf sur ses zones interactives. |
| **Bouton de signalement pilotable** | Le bouton de l'overlay suit une **variante** : visible ou non, couleur, taille, opacité, libellé, badge, animation, position. L'application change la variante à chaud (console de pilotage) pour inciter ou dissuader le joueur. |
| **Échanges avec le jeu** | Le jeu signale chaque **apparition** de bug. L'application peut demander au jeu d'en **déclencher** un (commande). |
| **Suivi** | Chaque variante réellement affichée est enregistrée (**affichage**, avec début/fin). Apparitions, interactions et signalements portent l'`affichage_id` en cours : chaque comportement est relié à sa cause. |

## 2. Architecture

```
 ┌──────────────── Jeu (page hôte) ─────────────────┐
 │  canvas du jeu                                   │
 │  SDK  /sdk/kapture-overlay.js                    │
 │   └─ iframe /overlay/  (transparente, plein écran)│
 └───────────────▲──────────────────────────────────┘
        postMessage │ (protocole §4)
                    ▼
         Overlay Vue ──── REST + SSE ────►  API Spring Boot  ◄──── REST + SSE ──── Console Vue (/pilotage, /suivi, /)
                                                  │
                                               MariaDB
```

- **Overlay ↔ API** : l'overlay ouvre `GET /api/sessions/{id}/flux` (Server-Sent Events) et reçoit variantes et commandes ; il envoie affichages, apparitions, interactions, signalements et résultats de commandes en REST.
- **Console ↔ API** : la console lit les sessions, pousse variantes et commandes, et suit tout en direct via `GET /api/flux` (SSE).
- Nginx relaie `/api/*` (SSE compris : `proxy_buffering off`).

## 3. Modèle de données (ajouts)

```sql
CREATE TABLE variante (               -- catalogue de variantes du bouton
  id         INT AUTO_INCREMENT PRIMARY KEY,
  code       VARCHAR(40)  NOT NULL UNIQUE,     -- ex. INCITATION_FORTE
  nom        VARCHAR(100) NOT NULL,
  intention  VARCHAR(20)  NOT NULL,            -- INCITER | NEUTRE | DISSUADER
  config     JSON         NOT NULL             -- ConfigBouton (§5.1)
);

CREATE TABLE affichage (              -- chaque variante effectivement affichée par l'overlay
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id   INT         NOT NULL,
  variante_id  INT         NULL,               -- NULL = configuration personnalisée
  config       JSON        NOT NULL,           -- copie exacte de ce qui a été rendu
  origine      VARCHAR(20) NOT NULL,           -- DEFAUT | OPERATEUR
  debut        DATETIME(3) NOT NULL,
  fin          DATETIME(3) NULL,               -- rempli au changement de variante ou à la déconnexion
  FOREIGN KEY (session_id)  REFERENCES session(id),
  FOREIGN KEY (variante_id) REFERENCES variante(id)
);

CREATE TABLE commande (               -- ordre envoyé au jeu par l'application
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id  INT          NOT NULL,
  type        VARCHAR(30)  NOT NULL,           -- DECLENCHER_BUG
  parametres  JSON         NOT NULL,           -- { "titre": "BUG3" }
  statut      VARCHAR(20)  NOT NULL,           -- ENVOYEE | EXECUTEE | ECHEC
  message     VARCHAR(200) NULL,               -- raison d'un échec
  cree_a      DATETIME(3)  NOT NULL,
  traite_a    DATETIME(3)  NULL,
  FOREIGN KEY (session_id) REFERENCES session(id)
);

CREATE TABLE apparition (             -- bug apparu dans le jeu
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id    INT          NOT NULL,
  titre         VARCHAR(100) NOT NULL,         -- BUG1 … BUG5
  origine       VARCHAR(20)  NOT NULL,         -- JEU (spontané) | COMMANDE (déclenché par l'application)
  commande_id   BIGINT       NULL,
  affichage_id  BIGINT       NULL,             -- variante affichée à cet instant
  payload       JSON         NULL,             -- état du jeu
  timestamp     DATETIME(3)  NOT NULL,
  FOREIGN KEY (session_id)   REFERENCES session(id),
  FOREIGN KEY (commande_id)  REFERENCES commande(id),
  FOREIGN KEY (affichage_id) REFERENCES affichage(id)
);

CREATE TABLE interaction (            -- comportement du joueur face au bouton
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id    INT          NOT NULL,
  affichage_id  BIGINT       NULL,
  type          VARCHAR(20)  NOT NULL,         -- SURVOL | OUVERTURE | ANNULATION
  details       JSON         NULL,
  timestamp     DATETIME(3)  NOT NULL,
  FOREIGN KEY (session_id)   REFERENCES session(id),
  FOREIGN KEY (affichage_id) REFERENCES affichage(id)
);

ALTER TABLE evenement
  ADD COLUMN affichage_id  BIGINT NULL,        -- variante affichée quand le joueur a signalé
  ADD COLUMN apparition_id BIGINT NULL,        -- apparition que le signalement couvre (si connue)
  ADD FOREIGN KEY (affichage_id)  REFERENCES affichage(id),
  ADD FOREIGN KEY (apparition_id) REFERENCES apparition(id);
```

Le catalogue de variantes est inséré au démarrage de l'API s'il est vide (§5.2).

## 4. Protocole jeu ↔ overlay (`postMessage`)

Tous les messages sont des objets `{ source, type, ... }`. Le SDK (`/sdk/kapture-overlay.js`) l'implémente côté jeu.

**Overlay → jeu** (`source: "kapture-overlay"`)

| `type` | Champs | Sens |
| --- | --- | --- |
| `ready` | `version` | overlay chargé |
| `zones` | `zones: [{x,y,w,h}]`, `capture: bool` | zones cliquables de l'overlay (px, repère de l'iframe). `capture: true` = panneau ouvert, l'overlay prend toute la souris |
| `passthrough` | — | le pointeur a quitté les zones : rendre les clics au jeu |
| `trigger-bug` | `commande_id`, `titre` | l'application demande au jeu de déclencher ce bug |
| `get-state` | `request_id` | demande l'état du jeu (payload) |
| `report-opened` / `report-closed` | — | le jeu peut se mettre en pause |
| `report-submitted` | `id` | signalement enregistré |

**Jeu → overlay** (`source: "kapture-game"`)

| `type` | Champs | Sens |
| --- | --- | --- |
| `bug` | `titre`, `payload` | un bug vient d'apparaître spontanément dans le jeu |
| `trigger-result` | `commande_id`, `succes`, `message?`, `payload?` | résultat d'un `trigger-bug` |
| `state` | `request_id`, `payload` | réponse à `get-state` |

Clics à travers l'overlay : le SDK met l'iframe en `pointer-events: none` et la réactive quand le pointeur entre dans une zone ; l'overlay envoie `passthrough` quand il en sort.

## 5. API v2

### 5.1 `ConfigBouton` (objet JSON)

```json
{
  "visible": true,
  "couleur": "#7c3aed",
  "taille": "M",
  "opacite": 1,
  "libelle": "Signaler un bug",
  "badge": { "mode": "texte", "texte": "!" },
  "animation": "pulsation",
  "position": "bas-droite"
}
```

| Champ | Règle | Message d'erreur (400) |
| --- | --- | --- |
| `visible` | booléen obligatoire | « La visibilité est obligatoire. » |
| `couleur` | `#rrggbb` | « Couleur invalide (format #rrggbb). » |
| `taille` | `S` `M` `L` `XL` | « Taille invalide. » |
| `opacite` | 0.1 … 1 | « Opacité invalide (entre 0.1 et 1). » |
| `libelle` | 0 … 40 caractères (`""` = icône seule) | « Le libellé ne doit pas dépasser 40 caractères. » |
| `badge.mode` | `aucun` `texte` `compteur` (compteur = apparitions non signalées) | « Badge invalide. » |
| `badge.texte` | 0 … 3 caractères | « Le texte du badge ne doit pas dépasser 3 caractères. » |
| `animation` | `aucune` `pulsation` `rebond` `secousse` `lueur` `respiration` | « Animation invalide. » |
| `position` | `bas-droite` `bas-gauche` `haut-droite` `haut-gauche` | « Position invalide. » |

### 5.2 Catalogue initial

| code | nom | intention | config (résumé) |
| --- | --- | --- | --- |
| `NEUTRE` | Neutre | NEUTRE | visible, `#64748b`, M, opacité 1, « Signaler », badge aucun, animation aucune, bas-droite |
| `INCITATION_DOUCE` | Incitation douce | INCITER | visible, `#7c3aed`, M, 1, « Signaler un bug », aucun, respiration |
| `INCITATION_FORTE` | Incitation forte | INCITER | visible, `#f43f5e`, L, 1, « Un bug ? Signale-le ! », texte « ! », pulsation |
| `INCITATION_COMPTEUR` | Compteur d'apparitions | INCITER | visible, `#f59e0b`, L, 1, « Signaler », compteur, rebond |
| `DISSUASION_DISCRETE` | Discrète | DISSUADER | visible, `#475569`, S, 0.35, `""`, aucun, aucune, haut-gauche |
| `MASQUE` | Masqué | DISSUADER | **visible: false**, reste identique à NEUTRE |

### 5.3 Routes

| Méthode | Route | Rôle | Réponses |
| --- | --- | --- | --- |
| `GET` | `/api/variantes` | catalogue | `200` `[Variante]` |
| `GET` | `/api/sessions` | sessions + état en direct | `200` `[SessionEtat]` |
| `GET` | `/api/sessions/{id}/flux` | **SSE overlay** : variante et commandes | `text/event-stream` · `404` session inconnue |
| `PUT` | `/api/sessions/{id}/variante` | assigner une variante (pousse aux overlays connectés) | `200` `SessionEtat` · `404` · `400` |
| `POST` | `/api/sessions/{id}/commandes` | demander au jeu de déclencher un bug | `201` `Commande` · `404` · `400` · `409` « Aucun overlay connecté pour cette session. » |
| `POST` | `/api/commandes/{id}/resultat` | l'overlay rend le résultat | `200` `Commande` · `404` « Commande inconnue. » · `409` « Commande déjà traitée. » |
| `POST` | `/api/sessions/{id}/affichages` | l'overlay confirme qu'il affiche une variante | `201` `{ "id": … }` |
| `POST` | `/api/sessions/{id}/apparitions` | le jeu (via l'overlay) signale un bug apparu | `201` `{ "id": … }` |
| `POST` | `/api/sessions/{id}/interactions` | survol / ouverture / annulation | `201` `{ "id": … }` |
| `GET` | `/api/sessions/{id}/chronologie` | tout ce qui s'est passé, trié par date croissante | `200` `[EntreeChronologie]` |
| `GET` | `/api/suivi/variantes` | statistiques par variante (`?session_id=` optionnel) | `200` `[StatVariante]` |
| `GET` | `/api/flux` | **SSE console** : chaque nouvelle entrée de chronologie + connexions | `text/event-stream` |

**Flux SSE**

- `/api/sessions/{id}/flux` — à la connexion : événement `variante` avec la variante courante. Puis `variante` (`SessionEtat.variante`) à chaque `PUT …/variante`, et `commande` (`Commande`) à chaque `POST …/commandes`. Commentaire `:ping` toutes les 15 s. À la déconnexion du dernier overlay : l'affichage ouvert de la session est fermé (`fin` = maintenant).
- `/api/flux` — événement `chronologie` (`EntreeChronologie`) pour chaque création (affichage, commande, résultat de commande, apparition, interaction, signalement) et `CONNEXION` (`details: { "connecte": bool, "overlays": n }`) à chaque (dé)connexion d'overlay. `:ping` toutes les 15 s.
